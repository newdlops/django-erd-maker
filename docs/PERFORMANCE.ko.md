# 0.0.1071 무캐시 재분석 측정

2026-10-05 현재 로컬 프로젝트에서 소스 탐색, Rust 분석, OGDF 배치,
최종 화면 기준 검증, HTML 문서 생성까지 측정했습니다. 모델·배치·학습
미리보기 결과 캐시는 읽지 않았으며, 요청마다 소스를 다시 분석했습니다.
실행 파일과 컴파일 산출물은 설치된 도구로 사용했습니다.

| 항목 | 일반 모드 | 최적화 모드 |
| --- | ---: | ---: |
| HTML 문서 준비까지 | 25.1초 | 77.2초 |
| 분석 호스트 + 네이티브 작업자 최대 RSS | 113.9 MiB | 118.4 MiB |
| 모델 수 | 1,247 | 1,247 |
| 비자기 관계 경로 수 | 1,732 | 1,732 |
| visualCross | 25,562 | 7,993 |
| 노드 겹침 | 31 | 70 |

소스에서 추출한 모델 1,251개 중 ID 충돌 4개는 기존 정규화 규칙으로
처리했습니다. 구조 관계 3,307개는 방향별 동일 연결을 합쳐 1,744개로
네이티브 배치기에 전달했으며, 자기 관계 12개를 제외한 1,732개 경로가 모두
결과에 포함됐습니다. 관계의 의미와 원래 필드 정보는 유지합니다.

측정은 Apple Silicon macOS의 단일 작업자에서 실행했습니다. 외부
메모리 감시기는 분석 호스트와 네이티브 작업자를 합산하여 128 MiB를
상한으로 적용했습니다. 실행 우선순위는 nice +10, 작업 스레드는
1개였습니다. 이 수치는 VS Code 전체 프로세스 메모리를 의미하지
않습니다. 컴파일 단계에만 최대 512 MiB를 허용합니다.

최적화 모드는 새 그래프의 클러스터 배치와 네이티브 관계 교차 개선을
실행합니다. 이번 재배치 후보는 visualCross를 낮췄지만 원래 경로의
교차 수가 증가하여 거부됐고, 완전한 기준 배치가 최종 결과로 남았습니다.
노드·관계 누락, ID 중복, 점이 2개가 아닌 경로도 후보 채택 전에 거부합니다.

visualCross 목표 500, 노드 겹침 0, 간격 위반 0은 아직 충족하지
못했습니다. 최적화 결과의 상태는 `quality-degraded`로 표시합니다.
이전 릴리스의 285 / 1,963 수치는 다른 그래프의 저장된 학습 미리보기이며,
이번 무캐시 재분석의 성과로 계산하지 않습니다.

별도 화면 검증에서는 실제 Electron/Chromium WebGPU로 생성된 HTML을
열었습니다. 로드부터 `webview.ready`까지 약 0.5초였으며, 1280×800,
768×1024, 390×844에서 문서 넘침과 GPU 경고가 없었습니다. 모델 선택과
Leaf cards 전환을 실행했고 페이지 오류는 없었습니다. 이는 위 재분석
측정과 별도로 확인한 것으로, 설치된 extension의 연속 첫 프레임 시간을
측정한 것은 아닙니다.

측정값은 이 프로젝트에서 한 번씩 확인한 결과입니다. 다른 프로젝트의
크기·연결 밀도·기기 부하에 따른 시간 차이는 남아 있습니다. 새 요청의
전체 분석에는 110초, 배치에는 최대 90초의 공유 마감 시간을 적용하여
무제한 분석이 UI 표시를 막지 않도록 했습니다.
